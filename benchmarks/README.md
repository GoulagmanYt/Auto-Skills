# Complete-task benchmarks

This harness measures completed code fixes, including executable validation. It is separate from the startup-context measurement in `tools/verify_context_savings.py`. No benchmark outcome is assumed in advance.

Plan the default three repetitions without making inference requests or downloading competitors:

```sh
python tools/benchmark_tasks.py --dry-run --model MODEL --arms baseline,auto-skills --repetitions 3 --output reports/benchmarks/plan
```

Run the same plan with an explicit model and authenticated local Codex CLI:

```sh
python tools/benchmark_tasks.py --model MODEL --arms baseline,auto-skills --repetitions 3 --timeout 180 --output reports/benchmarks/tasks
```

Use `--task midi-zero-velocity`, `--task frontend-reset`, or `--task rust-decoder-bounds` to restrict a run. Repeat `--task` for several tasks. CLI version `0.166.0` is required by default; a deliberate version change requires `--expected-codex-version VERSION`. Prefer an immutable model snapshot. The requested identifier is recorded exactly; a service alias does not establish an immutable underlying snapshot.

`--work-root .benchmark-work` places temporary task repositories under an explicit directory while preserving the `workspace-write` sandbox. This can help diagnose an outer environment that grants writes only below the current repository. Validators still execute from a separate directory outside each agent worktree. The report records the placement policy without publishing the absolute path.

If a smoke run exposes an infrastructure problem, preserve its failed report and expand the intended plan without paying for identical failed calls:

```sh
python tools/benchmark_tasks.py --model MODEL --arms baseline,auto-skills --repetitions 3 --blocked-preflight reports/benchmarks/smoke/report.json --output reports/benchmarks/blocked
```

This is an explicit operator decision, not an automatic assertion that every arm has the same defect. Mode `blocked` records each planned attempt as unavailable and unattempted, with null elapsed/usage measurements. Actual failed-preflight usage is retained separately and tied to the source report hash. It makes no native subprocess calls. Do not present these rows as three completed repetitions.

Each attempt starts with a fresh temporary Git repository containing identical public fixture bytes and a deterministic initial commit. Baseline and Auto-Skills use the same prompt, model, reasoning effort, sandbox and validation. Arm order rotates by repetition. The agent receives the code and task description. The validators and reference fixes stay outside its writable worktree. Before inference, the independent validator must reject the fixture. After inference, it must accept the patch, and every original fixture file other than the requested source file must remain unchanged. Agents may add local tests. No hardware, package installation or network access is needed for the three fixes or their validators.

The harness writes `report.json` and `report.md` after each attempt. Reports include fixture/validator/prompt hashes, fixture commit, requested model and CLI pins, per-run status and elapsed/setup/inference/validation time, native input/output/cached tokens when reported, and success/failure/unavailable counts. Performance medians and min/max use only attempts that passed independent validation, with separate total, inference and setup stages. All-attempt and failed-attempt timing metrics remain available separately, and reported usage totals include every known usage event, including failed attempts when present. Each metric reports its sample count; missing usage stays null. A task can pass while native usage is unavailable. No price, savings percentage or cache hit is fabricated. Raw native transcripts, arbitrary error text, environment variable values and authentication files are never saved. Diagnostic categories, event/item type counts and exit codes are retained instead. A failure removing an owned temporary task directory is reported separately as `cleanup_status: incomplete`; it does not change a completed independent validation result. Such directories remain under the ignored work root or system temporary directory for operator cleanup.

Codex runs as `exec --json --ephemeral --sandbox workspace-write` with explicit model and approval policy. All arms ignore user configuration and exec rules, except that an existing `windows.sandbox` backend (`elevated` or `unelevated`) is explicitly preserved on Windows. They disable memories and project documents, and explicitly disable unrelated skills, bundled skills, plugins and MCP servers. Child processes drop inherited `CODEX_*` orchestration variables except `CODEX_HOME`; persisted authentication and ordinary tool variables remain available. SkillRadar endpoint/registry overrides are cleared and its offline flag is set in every arm. Auto-Skills additionally receives its generated developer policy and offline tools. Its `launch_profile` and the control arm briefly create unique native profile files in the original `CODEX_HOME` and remove them in `finally`; authentication is neither copied nor changed. Native CLI cache/runtime side effects may still occur in that original home. The shared service cache is not reset. This measures an Auto-Skills treatment bundle, including policy and wrappers; it cannot isolate the effect of skill prose alone.

`--timeout` is the budget for one task attempt, including preparation. Individual Git, installation, validator and native calls also have bounded timeouts. A native timeout terminates its process group, with an additional bounded cleanup period. Missing runtimes, a mismatched CLI pin and unsupported competitor adapters produce explicit unavailable results. Any failed, timed out or unavailable attempt makes the CLI exit nonzero; dry-run exits zero when the plan is valid.

Optional competitor arms are defined in [competitors.json](competitors.json):

```sh
python tools/benchmark_tasks.py --model MODEL --arms baseline,auto-skills,vercel-skills,autoskills,skillradar --task frontend-reset --repetitions 3 --output reports/benchmarks/competitors
```

- `vercel-skills` uses exact npm `skills@1.7.6` with a checked-out, verified Git commit of Vercel React guidance. Its project-local installer, npm cache/prefix and downloaded source stay in the temporary attempt directory. The manifest records the npm integrity advertised by the registry; npm performs its normal package integrity checks. This is a manually selected React guide and is applicable only to the frontend task. Network/package availability and transitive installer dependencies can still vary.
- `autoskills` uses npm `autoskills@0.4.1` in the frontend workspace with `--yes --agent codex`. Its `AUTOSKILLS_REGISTRY_BASE_URL` names the exact reviewed source commit, removing the upstream default mutable-main fallback; `AUTOSKILLS_CACHE_DIR`, npm cache/prefix and home directories are isolated per attempt. The pinned installer writes native universal `.agents/skills` directories; it deliberately does not map Codex to a legacy `.codex` skill directory. Its selected recommendations are recorded as a treatment configuration, not assumed equivalent to Auto-Skills. This adapter currently covers the frontend fixture only.
- `skillradar` stages three unchanged files from the native Codex plugin's `v0.5.0` commit: its router `SKILL.md`, dependency-free lookup script and complete bundled registry. The original relative directory layout is retained in `.agents/skills/skillradar`, and only the router skill is enabled. An independent setup check requires `source: skillradar-registry`, `registry.mode: local-bundled` and ranking version `2.1`. This measures a selected project-local router bundle, not native marketplace/plugin installation, the separate mutable-network standard skill, or automatically downloaded implementation guidance. The common coding prompt may not activate routing; installed guidance is not proof it was used. This adapter currently covers the frontend fixture only.

The package versions were checked against the primary [skills npm registry](https://registry.npmjs.org/skills/1.7.6) and [autoskills npm registry](https://registry.npmjs.org/autoskills/0.4.1). Native installation behavior is documented by [Vercel skills](https://github.com/vercel-labs/skills/blob/7a5e920bead4b1039a6d6df5d7e1163b7b09423a/docs/commands.md) and [SkillRadar](https://github.com/changchangidea-oss/SkillRadar/tree/6354ef44bfe9a8502f4371674ec1c4f8cac5cc56). Codex's [official non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode) describes JSON completion usage and ephemeral execution; local CLI help determines supported flags for the pinned version.

Three small synthetic tasks and three repetitions are a reproducibility smoke test, not evidence of general superiority. Review task success together with latency, usage availability, failed attempts and all policy confounds before drawing conclusions.

Local preflight evidence on 2026-11-04 used Codex `0.166.0`, requested model `gpt-6.1-sol`, baseline and `workspace-write`. A diagnostic MIDI attempt exited zero but changed no code and failed the independent validator; its final agent message reported read-only filesystem access and a rejected inspection command. It took 15.31 seconds and reported 61,481 input tokens, 46,976 cached input tokens, 286 output tokens and 14 reasoning output tokens. A subsequent attempt with its worktree under the outer repository also changed no code and failed validation: 19.211974 seconds, 88,443 input, 73,728 cached input, 311 output and 21 reasoning output tokens. Neither emitted tool execution events. Moving the worktree alone did not resolve the environment restriction. These are failed infrastructure preflights, not successful task runs or comparative results; repeated inference was stopped rather than treating exit zero as success.

Recovery on 2026-11-05 tested two controlled MIDI variants. Removing inherited `CODEX_*` orchestration context alone still produced no tool execution or patch and failed validation (20.429227 seconds, 113,645 input / 92,544 cached / 322 output tokens). Keeping that environment treatment and explicitly restoring the existing `windows.sandbox="elevated"` backend produced a real `midi_state.py` patch and passed the external validator (55.247483 seconds, 195,393 input / 171,648 cached / 1,412 output tokens). The older harness then mislabeled that attempt unavailable because cleanup raised `PermissionError`; the preserved diagnostic report retains that historical status and its successful `after_validation` evidence. The harness now records cleanup independently. This supports the Windows backend configuration as a cause in this environment; it does not prove sanitizing orchestration variables is necessary or establish a general Codex defect. Both variants retained `workspace-write` and approval policy `never`; no sandbox bypass was used.

The historical `blocked` report remains an unexecuted 45-row plan. Recovery preflights and new measured repetitions use separate report directories. Isolated setup checks also installed five pinned autoskills recommendations in 8.625 seconds and executed SkillRadar's bundled registry lookup in 1.55 seconds; these setup checks are not task performance results.

The final Auto-Skills MIDI recovery preflight with the corrected `1.4.0a1` launch policy passed the independent validator, changed only `midi_state.py`, emitted six command executions and two file changes, and completed cleanup. It measured 52.245834 seconds and native usage of 220,468 input / 195,712 cached / 1,476 output / 8 reasoning tokens. This was the third and last recovery diagnostic request, separate from the repeated comparison matrix.

Interrupted runs can be resumed with the same model, arms, repetitions, task selection, timeout and launch policy:

```sh
python tools/benchmark_tasks.py --resume reports/benchmarks/tasks/report.json --model MODEL --arms baseline,auto-skills --repetitions 3 --timeout 180 --output reports/benchmarks/tasks
```

Resumption validates model/CLI/product-version, task/fixture/prompt/validator, competitor and policy pins before making a native call. It preserves recorded failures and successes, adds a separate startup harness/source receipt for each resumed batch, and never retries completed rows. Each new slot is journaled as `in_flight` before execution. An unrecorded in-flight slot becomes `interrupted` with unknown usage and is not replayed. For an older receipt without an in-flight journal, the explicit `--assume-first-pending-interrupted` flag conservatively accounts for a possibly started first pending slot without replaying it. The first genuinely unstarted request also serves as a service check; a native/process failure stops further inference, records remaining applicable slots `not_attempted`, and retains inapplicable combinations separately. Interruption and unattempted rows do not count as validated product failures.

JSON is the canonical receipt; current harness writes replace JSON and Markdown atomically, so an interrupted replacement leaves the previous receipt valid. Keep an independent snapshot before resuming old non-atomic runs. The actual November 5 recovery resume began just before this atomic-write improvement landed; its original startup receipt is retained, and no paid call was restarted to change writer implementation.

The curated November 5 comparison is in [reports/benchmarks/comparison/analysis.md](https://github.com/GoulagmanYt/Auto-Skills/blob/801b1e037448123553ad1301736df93c46a3025d/reports/benchmarks/comparison/analysis.md), with full per-run receipts in [report.json](https://github.com/GoulagmanYt/Auto-Skills/blob/801b1e037448123553ad1301736df93c46a3025d/reports/benchmarks/comparison/report.json). All 45 slots are accounted for: 17 validated passes, 9 native execution failures, 18 adapter/task-scope exclusions and 1 interrupted slot whose attempt state is unknown. The original 34 recorded row objects were preserved during resumption; seven genuinely remaining requests all passed. Eight earlier generic native exit-1 causes remain unresolved, and the unusual ninth exit occurred before any tool event. Source batches and service/cache state differed. These observations do not support a general winner, a causal speed ranking or a token-savings claim.
